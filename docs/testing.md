# Проверки и структура исходников

## Логика

Из корня репозитория, Node.js без дополнительных зависимостей:

```sh
node --test core.test.mjs controller.test.mjs keys.test.mjs create-book.test.mjs notifications.test.mjs
```

70 проверок покрывают источники и авторство, устаревшие сообщения, метки, пороги автоматизации, этапы анализа и их очистку, ошибки и отмену, сохранение и восстановление, откат, создание книги и целостность regex-ключей.

Приоритет: ручной режим с допустимым нулём, автоматическая нумерация и обратный порядок для двух разных разделов; чужая запись не влияет на номер, дополнение сохраняет вручную изменённый приоритет. Браузер проверяет переключение всех режимов и фактическое сохранение заданного приоритета при автоанализе.

Ссылки на абзацы: разбиение LF/CRLF, сохранение разметки и строк исходника, подстановка оригинального текста/авторства вместо полей модели, запрет неизвестных ID и подмены через legacy quote, полный путь sourceId от промпта до источников записи, блокировка изменённого контекста. Браузер сохраняет предложение без скопированной цитаты. Прежние проверки точных цитат остаются для обратной совместимости.

Результаты: 45 тестовых анализов, страницы 20/20/5, доступ к старым данным, фильтры находок и ожидающих решения, сохранение ошибок цитат в фильтре и отсутствие мутации журнала. Браузер проверяет селектор, страницы, общий фильтр «Находок»/«Сцен», ширину 320 px и подписи удаления/восстановления при откате.

Кастомные категории: обязательная ручная очередь при автоанализе, запрет автоматического создания, переименование без потери правок, повторное использование ID и полного текста, перенос в существующий раздел с прежними фактами и ключами, запрет стандартных и повторных названий и неизвестных custom-ID. Браузер проходит предложение, переименование, сохранение и перезагрузку на 320 px.

Проверяется передача полного текста раздела и выбранной политики событий в реальный запрос контроллера с пользовательским промптом. Браузер проверяет выключенное исходное состояние переключателя, сохранение настройки и её применение при автоанализе. Ответы модели имитируются; качество реального редактирования этими тестами не оценивается.

## Браузерный сценарий

`tests/browser.mjs` использует установленный Playwright с Firefox. Это инструмент разработки, а не зависимость расширения.

```sh
node tests/browser.mjs
```

При нестандартной установке доступны переменные:

| Переменная | Назначение |
|---|---|
| `PERSONA_CANON_PLAYWRIGHT_MODULE` | Имя установленного модуля или абсолютный file URL до `playwright/index.mjs` |
| `PERSONA_CANON_FIREFOX` | Путь к совместимому Firefox из установки Playwright |
| `PERSONA_CANON_SCREENSHOTS` | Необязательный каталог снимков |

Стенд запускает временный HTTP-сервер, загружает настоящий entrypoint расширения и подменяет API/модули ST. Рабочие книги, реальные провайдеры и платные запросы не используются. Если рядом установлена CSS-библиотека Font Awesome SillyTavern, дополнительно проверяется существование выбранной иконки.

Проверяется регистрация только в палочке, название manifest, открытие мышью/клавиатурой, отсутствие дубликатов, IndexedDB после перезагрузки, все три источника, загрузка моделей, история и откат, автоматическое создание книги и записи, отсутствие ключа в сохраняемых настройках, вывод недоверенного текста и ширины 320/390/768/1440 px.

Геометрия окна проверяется при смене источника и при задержке загрузки записей; сенсорные элементы проверяются отдельно.

## Границы проверки

Успех стенда не доказывает совместимость с любым провайдером или семантическую точность модели. Реальные запросы и пользовательские книги при подготовке этой версии не затрагивались. Синтаксис JS проверяется через `node --check`; ESLint в текущем окружении разработки не установлен.

## Файлы

| Файл | Назначение |
|---|---|
| `index.js` | Адаптер ST, регистрация палочки, настройки и события автоматизации |
| `ui.mjs`, `style.css` | Интерфейс находок, записей, сцен, истории и настроек |
| `controller.mjs` | Анализ, очередь, журнал операций, сохранение и откат |
| `automation.mjs` | Пороги автоматического анализа и политика автосохранения |
| `connections.mjs` | Источники запросов, модели, тайм-ауты и ошибки |
| `prompt.mjs` | Исходные инструкции и обязательный контракт ответа |
| `keys.mjs` | Проверка и разбор regex-ключей без разделения внутренних запятых |
| `core.mjs` | Валидация предложений, источники, покрытие сцен и метки |
| `sections.mjs` | Фиксированные названия, один раздел на категорию и проверка целей обновления |
| `view-state.mjs` | Страницы и фильтры результатов, понятные статусы истории |
| `evidence.mjs` | ID абзацев и извлечение оригинальных источников |
| `create-book.mjs` | Проверка имени, создание и привязка книги |
| `storage.mjs` | Локальная очередь и история в IndexedDB |
| `manifest.json` | Метаданные загрузки расширения |

`Persona-Canon` в технических идентификаторах и названиях тестовых переменных — сохранённое внутреннее имя, а не название в интерфейсе.

Уведомления: проверены запуск/завершение, отсутствие спама ниже порога, частичное сохранение, потерянное подтверждение сервера, недоступный журнал, экранирование HTML и скрытие ключа. Браузерный сценарий проверяет путь от события автоматизации до вызова штатного toastr.

Регрессия фонового анализа: задержанный ответ модели, открытие/закрытие и повторное открытие окна при ручном и автоматическом запросе, видимый этап и блокировка повторного запуска, завершение с автосохранением, отдельная отмена без записи и без отметки сцены. Индикатор проверяется на ширине 320 px.

Регрессия цитат: смешанный ответ с корректной находкой, сокращением через `[...]` и неверным номером сообщения. Проверяются отдельные причины отказа, исходный текст, экранирование HTML, сохранение только корректной находки и диагностики после перезагрузки, отсутствие покрытия у неполного результата и отсутствие кнопки сохранения при полностью отклонённых цитатах. Модульные проверки также покрывают сохранение обязательных правил при пользовательском промпте, отдельные непрерывные отрывки, буквальные многоточия в источнике и паузу автоматических повторов.

Разделы: создание всех шести фиксированных записей, добавление второго человека в ту же запись «Отношения», передача прежнего текста и ID модели, сохранение ключей и настроек, преобразование одиночной старой записи при принятии правки и обратимый откат. Проверяются запрет нескольких предложений одной категории, неверных целей, устаревших находок и второго экземпляра раздела при позднем сохранении или восстановлении операции. Несколько старых записей останавливают анализ до платного запроса. Браузер проверяет реальные названия в сохраняемой книге и обновление существующей записи через UI.
